# UX & motion conventions (Renly frontend)

Applies to every component/page in `apps/web` and `packages/ui`. Load alongside `web-components-pages` (where files go) and `web-structure`.

## Two surfaces — know which you're building

- **App** — the authenticated product + its auth flows: `app/(auth)/` (login, signup, forgot/reset/verify) and `app/(protected)/` (dashboard, investments, settings, …). Motion is **calm and functional**: feedback and orientation, never spectacle. It's a tool people use daily.
- **Public** — the marketing surface reachable without logging in: the `app/(public)/` route group (landing, privacy, terms, disclaimer). Motion is **expressive and vibrant** (on-load entrance, scroll-reveal, hover-float, ambient), built on the same base below.

The **Base conventions** apply to BOTH. **App motion** and **Public motion** layer on top — pick by surface.

## Base conventions (all surfaces)

### Interaction states — every interactive element gets all that apply

- **focus-visible — never leave the browser default.** Always `outline-none`, then replace with the Renly treatment:
  - **Surfaces** (buttons, inputs, focusable cards/controls): the ring, exactly like `packages/ui/src/components/button.tsx` — `outline-none focus-visible:ring-3 focus-visible:ring-ring focus-visible:border-ring`. The default ring is the app's blue and **solid — never `ring-ring/<alpha>`**: `--ring` is dark enough to clear WCAG 1.4.11's 3:1 on every surface, and halving it is what once measured 1.2:1 (a unit test refuses the alpha; an e2e spec measures the painted ring). Variant-tinted rings use `focus-visible:ring-<color>/50` (destructive `ring-danger/50`, blue `ring-blue-800/50`). A field's **hover** border is `hover:border-border-3`, not `hover:border-ring` — the ring token is the focus colour, and keeping hover lighter is also what makes focus read differently from it.
  - **Icon-only / inline triggers**: the focus-bump family via a focusable group — `group/<name>` on the focusable element + `group-focus-visible/<name>:animate-<x>` on the icon. Utilities (in `packages/ui/src/styles/index.css`): `animate-focus-bump` (scale 1.5, icon buttons), `animate-focus-bump-soft` (1.15, inline), `animate-focus-bump-subtle` (1.05, text links), `animate-pulse-scale` (0.95 press-in, toggle/segmented). Reference: the table sort headers. An icon button that GROWS on hover (`hover:scale-110` — the password eye, a field's clear ✕, a hint's dismiss, a chip's remove) still takes the bump for focus: never `focus-visible:scale-*`, which makes focus and hover identical (a unit test refuses it).
  - Keyboard focus MUST be as visible as hover. Audit every element you add — no missing ring, no leftover native outline.
- **close (✕) controls** — anything that closes, dismisses, clears or removes is one of four kinds, and takes that kind's classes from `CLOSE_CONTROL` (`packages/ui/src/lib/close-control.ts`) plus `data-close-kind="<kind>"` — never a hand-styled ✕. Every kind has `outline-none`, a SOLID `ring-ring` on keyboard focus (like every other button) and the focus-bump on the icon via the shared `group/close`. They differ where their context does:
  - `surface` — closes a whole surface: the dialog and sheet ✕ (built into `DialogContent` / `SheetContent`), a dismissable card. 24px box in the corner, 16px icon, muted → foreground with the ghost button's `bg-muted` on hover, no scale (a corner control on a calm surface). Ring + bump.
  - `inline` — dismisses a one-line hint from inside it (`StyledHint`'s `onDismiss`). 24px box pulled into the line (`-my-1`) so the hint keeps its height, 14px icon in the hint's own intent colour at half strength, full on hover/focus, grows on hover. Ring + bump.
  - `field` — clears the field it sits in or over (`SearchInput`, the currency combobox). Looks like `inline` in the field's muted colour, but the ring is the FIELD's: the Input's `focus-within` ring, or `FIELD_CLEAR_RING` on the wrapper of a field the ✕ sits over — as with the password toggle, so focus never draws a ring inside a ring. Bump only on the ✕ itself.
  - `chip` — removes one selection from inside its 20px pill (`ComboboxMultiSelect`). 16px circle, 12px icon, muted → `text-danger` and growing on hover (it removes). A 2px ring, which stays in the 6px gap between chips where a 3px one would cover the next pill. Ring + bump.
  - A ✕ that is one of a table row's actions (revoking an invite) is a `RowActionButton` like its siblings, not a close control. `tests/unit/close-controls.test.ts` derives every lucide `X` and refuses one outside these rules; `focus-system.auth.spec.ts` measures the ring and bump of one of each kind.
- **skip link** — every layout that puts navigation ahead of its `<main>` renders the shared `SkipLink` (`apps/web/components/skip-link.tsx`) as its FIRST element and gives the `<main>` `id={MAIN_CONTENT_ID}` + `tabIndex={-1}` (plus `outline-none`), so the first Tab offers to jump past the sidebar/header and Enter lands focus in the page's content. A unit test derives the population from every `layout.tsx` rendering a `<main>`; a layout whose `<main>` comes first (the auth card) is exempted there with its reason.
- **inline text links & actions** — text rendered as a link OR an inline action (auth links, footer/legal links, a wordmark-as-home link, an in-page action such as replaying a tour), not a full button: use the shared inline-link component, `InlineLink` (`apps/web/components/inline-link.tsx`) — never build a new one. Pass `href` for navigation or `onClick` for an action (it renders a `<Link>` or a `<button>` with identical styling), plus `color`/`size`/`className` and an optional leading `icon` (rotates on hover, like the nav items). A link INSIDE running copy (a hint, a paragraph, a table cell) takes `size="inherit"`, so it keeps the copy's size and line height: the default `sm` is 14px, and inside a 12px hint it drew bigger and pushed the line down. It MUST: animate the underline on hover (`underline decoration-transparent underline-offset-2 … hover:decoration-<color>` + `transition-colors`) — put the hover on the underlined text itself (self-`hover:`), NOT a named-group `group-hover/…` variant on that same element (it compiles to a descendant selector that never matches the element hovering itself); give a focus-visible cue **distinct from hover** (`focus-visible:animate-focus-bump-subtle`); and drop the native outline (`outline-none`). Never a bare `<a>`/`<button>` with ad-hoc classes.
- **text beside an icon sits optically centred** — an icon + label row is `flex items-center`, which centres the label's LINE BOX on the icon, and the app font is set up so that is also where the letters' optical middle is (halfway between the centre of a capital and of a lowercase letter). `apps/web/lib/fonts/plus-jakarta-sans.ts` overrides the face's vertical metrics to ascent 96% / descent 30% for that — its comment derives the numbers; with the font's own metrics labels drew up to 1.9px low. So never nudge a label with `mt-px`/`translate-y` or pad an icon to "fix" centring: if a row looks off, the row is not a plain `items-center` row. The one cost: an accented capital (Á, É) reaches above the 0.96em ascent, so text in a box that clips its overflow needs a line height of at least ~1.35, never a tight one with `truncate`/`overflow-hidden`. `optical-centring.auth.spec.ts` measures every icon + text row on a set of pages and fails a row more than 1px off its icon, or rows that sit more than 0.5px off on average (whole-pixel baseline rounding leaves single rows up to about a pixel off, by platform).
- **in-page anchor navigation** (a table of contents, a "jump to" list) — scroll **smoothly** to the target, never a hard jump. Render the links as plain `<a href="#id">` (NOT a Next `<Link>`, which intercepts the click and fights the scroll) and put the shared `useSmoothScrollToHash()` hook (`apps/web/lib/hooks/`) as a delegated `onClick` on the links' container: it calls `scrollIntoView({ behavior: 'smooth', block: 'start' })`, honors reduced motion (an explicit `'instant'` jump), updates the URL hash via `replaceState`, and moves focus to the target so keyboard/screen-reader users continue from the section, not the link. Give each scroll target a `scroll-mt-*` so it lands clear of the sticky header. Reuse the hook — never hand-roll `scrollIntoView` / a global `scroll-behavior: smooth` (the latter also animates Next's scroll-to-top on every route change) per page.
- **hover** — pair EVERY hover with a matching focus-visible (keyboard parity). `transition-colors` for color, `transition-all duration-200` for scale, `transition-[border-color,box-shadow]` for inputs. Don't signal interactivity with color alone (add scale/shape/underline). An icon inside an interactive element animates on the element's hover via `group-hover` — e.g. a small rotate, like the sidebar nav items — paired with the focus-bump (`group-focus-visible/<name>:animate-…`).
- **a toggle that saves on its own** (its click IS the save) — flips at once and stays interactive while it saves; never `disabled` while its write is in flight. Build it on `useAutosaveToggles` (`apps/web/lib/hooks/`), which coalesces a burst into one write and rolls the control back on a failure — see web-components-pages.
- **active / pressed** — give pressed feedback where it reads: `active:bg-<token>` (buttons already do this) or `active:scale-95` / `animate-pulse-scale` for toggles.
- **disabled** — `disabled:opacity-50 disabled:pointer-events-none` (button base); non-disabled buttons / `[role=button]` get `cursor-pointer` (base rule in `index.css`).

### Status colours — semantic tokens, never a palette shade

- **Use the intent tokens** from `packages/ui/src/styles/index.css`: `success`, `warning`, `danger`, `info`. Each intent has ONE foreground for text AND icons (`text-success`, the 700 step: ≥ 4.5:1 on background, card, input, muted and its own tint), a tint `bg-<intent>-subtle`, a hairline `border-<intent>-border`, and for danger a solid fill with white text (`bg-danger-solid`, `hover:bg-danger-solid-hover`, `active:bg-danger-solid-active` — the destructive button). A badge or callout is the triplet `bg-<intent>-subtle border-<intent>-border text-<intent>`.
- **Money direction uses the aliases** `text-gain` / `text-loss` (an amount owed, like a card balance, is a loss), so the call site says what the colour means and the mapping lives in the token file. Health thresholds (good / caution / bad) use the intents. Chart marks use `--chart-gain`, `--chart-gain-soft` and `--chart-loss` through `lib/constants/charts.ts`.
- **Never a raw status hue** — no `text-red-500`, `bg-emerald-50`, `ring-amber-500/40`, no red/green/amber `oklch`/hex literal, no `var(--color-red-500)`. `tests/unit/status-colour-tokens.test.ts` refuses all three outside the token file. A new shade or intent goes in the token file (and its `theme.css` mapping), measured against the surfaces it lands on.
- **Never colour alone** (WCAG 1.4.1): a sign (`fmt.signedValue`, `fmt.signedPct`), an arrow or a word carries the state too.

### Motion stack & timing

- Library: **`motion/react`** (`import { motion, AnimatePresence, LayoutGroup } from 'motion/react'`) — not framer-motion.
- Durations from `apps/web/lib/constants/animations.ts`: `ANIMATION_FAST` 0.15 / `ANIMATION_DEFAULT` 0.25 / `ANIMATION_SLOW` 0.5. **Never hardcode a duration** — add a shared constant if you need a new one.

### No layout shift (hard rule)

- Micro-interactions animate **transform + opacity only**.
- Reflowing siblings → `motion`'s `layout` prop + `AnimatePresence mode="popLayout"` (+ a negative margin to absorb the gap). Height reveal → `height: 0 ↔ 'auto'` + `overflow: hidden` + `initial={false}` (so it doesn't animate on mount).
- Toggling an icon between states → stack both in one grid cell (`col-start-1 row-start-1`) and crossfade with `scale-0/opacity-0` (password eye, sort icons) — never reflow.
- Reserve space for conditional content; use fixed icon sizes (`size-4`).

### Open / close — both directions

- Reuse the `@repo/ui` primitives' built-in open/close: dialog/popover/tooltip/sheet use `data-[state=open]:animate-in / data-[state=closed]:animate-out` + `fade` / `zoom-95` / directional `slide-in-from-*` (sheets are asymmetric: 500ms open / 300ms close). Collapsible → `animate-collapsible-down/up`. Don't reinvent these.
- Crossfade loading/empty/content via `AnimatePresence mode="wait"` + a ~500ms min-loading delay (credit-cards settlements pattern).
- **Navigation keeps the page until the next one is ready (every protected route).** There is no route loading state and no entrance: a navigation leaves the old page on screen until the new one is complete, then swaps it in at once — no fade, no placeholder in between. Never add a `loading.tsx` or a `template.tsx` fade under `app/(protected)`: React keeps a mounted route loading state for ~300 ms however soon the page is ready, so every click got slower and blanked `<main>` (`tests/unit/no-route-loading-state.test.ts` refuses one, and `navigation-no-blank.auth.spec.ts` samples every frame of a click to every sidebar page). The click is answered instead by `NavigationPendingProvider` (`app/(protected)/_components/navigation-pending.tsx`, in the protected layout): the destination's sidebar item turns active on the click itself (and goes back if the navigation is dropped), and past `NAVIGATION_PENDING_DELAY_MS` (150 ms) a 2px brand-blue (`bg-blue-800`, the focus ring's blue) progress bar sweeps across the top of the main column while the old page dims to 0.6, `aria-busy` and taking no pointer input inside `<main>` only (keyboard focus is untouched) — the sidebar and the bell stay usable, so another click takes over. Both go in the frame the new page arrives; a faster navigation shows neither. A link click anywhere is seen by the provider with no wiring (it captures clicks on the document; modifier/middle clicks, `target`, `download`, other origins and `#` jumps are ignored) and so are back/forward; code that navigates itself goes through `usePendingRouter()` (`lib/hooks/`), never a bare `router.push` — a query-only navigation (a filter, a period, a page) gets the bar but no dim, beside any pending state of its own (`isPending`). Reduced motion: the bar is a still full-width line and the dim has no transition. `navigation-pending.auth.spec.ts` pins the timing.
- **A page arrives whole; speed comes from its reads, not from a placeholder.** A page starts every read as early as its inputs allow (web-structure), so it is ready in one or two API round trips. Do not stream a section behind an in-page `<Suspense>` without measuring it: once its placeholder is on screen React holds it for at least ~300 ms (measured on the main dashboard: the frame came at ~110 ms but the figures at ~410 ms, against ~235 ms for the whole page unstreamed), so it only pays for reads slower than that. A placeholder that is used must be the section's exact size for every account — data-shaped parts (an optional line, a legend's length) cannot be — and the base `Skeleton`'s pulse is gated with `motion-reduce:animate-none`.
- Never conditionally unmount in a way that kills the exit — use `AnimatePresence` exits so **close looks as good as open**.
- **Dialogs — keep the content mounted through the exit.** Toggle only the dialog's `open`; pass its row/detail data as a **stable prop** rather than nulling it on close (nulling blanks the body, so the dialog visibly shrinks then vanishes instead of a clean fade + zoom-out). Reset any derived state _after_ the animation (a timeout), never mid-exit. **Focus returns to whatever opened it** on every close (Escape, ✕, Cancel, overlay): the base `DialogContent` and `SheetContent` do it through `useReturnFocus` (`packages/ui/src/hooks/`), for controlled dialogs too — Radix alone only returns to its own `Dialog.Trigger`, which this app almost never renders. The opener is recorded when the content element mounts (the hook's `ref`), so it also holds for a dialog whose field takes focus with `autoFocus` (Radix skips its open event then), and a caller's own `onCloseAutoFocus`/`ref` are composed by the hook, not dropped. Never add a per-dialog `onCloseAutoFocus` just to refocus a trigger, and never wrap the Radix dialog anywhere but those two files (a unit test derives the wrappers from the import). The base `@repo/ui` `Dialog`'s close ✕ is the `surface` close kind (see close controls above: the solid ring and the icon's focus-bump) — use it, don't re-style the ✕ per dialog.
- A control's **open/closed state icon** (a select / combobox / disclosure chevron) rotates on open. Drive it off the open state (a prop, or `group-data-[state=open]`) and animate with **`transition-transform`** — in Tailwind v4 `rotate-*` sets the `rotate` property, so a `transform`-only transition does NOT animate it (the chevron snaps). Put the rotating chevron in one **shared component** so every dropdown's affordance (icon, size, rotation) is identical — don't re-implement it per call site.

### Reduced motion (mandatory)

Honor `prefers-reduced-motion: reduce`. Non-essential motion (scroll reveals, floats, parallax, large scale/translate, ambient loops) collapses to instant / opacity-only. Functional feedback (focus ring, small hover) may stay. Two app-wide mechanisms already do this, so a component built on the stack below is correct by default. **Don't hand-roll a per-component gate for either.**

- **motion/react:** the root layout wraps everything in `MotionProvider` (`apps/web/components/motion-provider.tsx`), a `MotionConfig reducedMotion="user"`. Under `reduce`, motion makes only the POSITIONAL values instant: transforms (x/y, scale, rotate), width/height, top/left/right/bottom, and `layout` animations. Everything else still animates: opacity and color, but also margin and padding. So a call site that tweens a margin (e.g. the `marginRight: -12 → 0` that absorbs a flex gap in a side-by-side field reveal) must make that value instant itself: `useReducedMotion()` plus a per-value `transition={{ duration: …, ...(reduceMotion && { marginRight: { duration: 0 } }) }}`, as the expense and investment form dialogs do. Otherwise reach for `useReducedMotion()` only when the right reduced behavior is something other than the default: a different variant (the public `Reveal`), an `'instant'` scroll, or an animation motion doesn't drive (the Shepherd tour). Never render motion outside the root layout's tree.
- **The primitives' open/close (tw-animate-css `animate-in` / `animate-out`):** one unlayered `@media (prefers-reduced-motion: reduce)` block in `packages/ui/src/styles/index.css` resets the `--tw-enter-*` / `--tw-exit-*` scale, translate and rotate variables on anything carrying `animate-in` / `animate-out`. That makes every `zoom-*` / `slide-*` / `spin-*` enter and exit opacity-only, and one with no fade of its own (the Sheet's slide) gets one. It gates the animation FAMILY, so dialog, popover, select, tooltip, sheet and any future primitive or element built from these utilities need no extra CSS. The animation still runs, which Radix Presence needs in order to unmount on close.
- **Anything else in CSS** (a custom `@keyframes`, a third-party widget's transitions): gate it with its own unlayered `@media (prefers-reduced-motion: reduce)` next to the rule, like the Collapsible and Shepherd-tour gates. Unlayered beats every `@layer utilities` rule, and an attribute-substring selector (`[class*='animate-x']`) matches the utility under any variant.

## App motion (`(auth)` + `(protected)`)

Calm and functional: state feedback (focus/hover/active), the primitives' open/close, conditional-field reveals, loading crossfades, and at most a quiet on-mount fade (the auth cards). Protected pages swap in at once on navigation (above). **No scroll-reveal, no ambient/decorative motion** — keep it quiet.

- **State transitions between distinct steps** (e.g. an upload → review wizard, or any swap between mutually-exclusive panels) crossfade with `AnimatePresence mode="wait"` + opacity — don't snap from one state to the next.
- **A control's changing label/count animates, including its size.** When a button (or similar) label changes — e.g. a count updating — crossfade the text with a keyed `AnimatePresence`, and animate the control's **resize both ways** (grow and shrink) with the `layout` prop. Wrap a base component to make it animatable (`motion.create(Button)`); the bare CSS `transition-all` does not animate content-driven `width: auto` changes.

## Public motion (`(public)`)

Expressive but standards-based, on the same tokens/rounding/stack. The public surface deliberately animates **more** than the app — that contrast is intended, not a violation of the calm-app rule.

- **Animate on load AND on scroll.** The first view animates in on mount (hero fade + small rise); every section below reveals as it scrolls into view. (The app does neither — this is the public differentiation.)
- **Scroll-reveal:** `whileInView` + `viewport={{ once: true, margin: '-10% 0px' }}` (reveal once, never replay on scroll-up). opacity + small `translateY` (~16–24px). Stagger groups (~0.06–0.1s). Content must be SSR'd and readable without JS — reveals are progressive enhancement, never a gate.
- **Hover micro-interactions:** card lift (`translateY(-6…-8px)`) + shadow, transform/opacity only, ~150–250ms; pair with focus-visible.
- **Hover-lift without flicker (gotcha + fix):** when an element lifts on hover, the element that OWNS the hover must NOT move — otherwise the pointer falls outside the moved element at the boundary and it oscillates hover→un-hover→hover forever. Keep the hover/layout box stationary and lift an **inner** layer, or drive the lift from a stationary wrapper that owns the `:hover`/`whileHover`. Motion must be smooth in BOTH directions (same easing + duration in and out).
- **Ambient / float:** subtle hero accents only; always gated by reduced-motion.
- **Footer:** differentiate it from the page body — a subtle surface tint and/or a top border via the shared `Separator` (don't hand-roll `border-t`), optionally a soft shadow on the divider. Footer/legal links use the inline-link component above.
- **Sticky / translucent header — overscroll bleed:** a sticky, semi-transparent header shows a seam at the very top when the page overscroll-bounces. Back the overscroll area with the header's color (extend the header background upward, or paint a fixed top layer in the header color) so no line shows — without disabling overscroll/overflow.
- **Performance:** transform/opacity only (60fps); avoid animating width/height/blur; `will-change` sparingly.

## Verify (playwright-cli, per `e2e-testing`)

Keyboard focus-visible on every interactive element; hover; open AND close; (public) on-load entrance + scroll reveals firing once; hover-lift smooth both ways with no boundary flicker; and the reduced-motion fallback (emulate reduce).
