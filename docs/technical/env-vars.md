# Environment Variables

All environment variables used by the Renly backend and frontend, with defaults and descriptions.

## Backend (`apps/api/.env`)

| Variable                      | Required | Default                         | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------- | -------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                | Yes      | —                               | Async Postgres connection string (`postgresql+asyncpg://user:pass@host:port/db`) for request connections. Must be the **restricted `renly_app` role** (NOBYPASSRLS, not the owner, not a superuser) so Row-Level Security applies (SEC-15). Every policied table is `FORCE`d, so a NOSUPERUSER owner is subject to the policies too; a superuser is not. With `ENVIRONMENT=production` the API refuses to start when this role, or the owner of any policied table, is `SUPERUSER` or `BYPASSRLS`, when this role is a member of such a role or owns (or is a member of the owner of) a policied table, or when a policied table is not `FORCE`d; it also needs the database reachable at boot ([deployment](deployment.md#roles)) |
| `DATABASE_ADMIN_URL`          | No       | falls back to `DATABASE_URL`    | Privileged connection for context-less work: the scheduler, notification dispatch, Alembic migrations, and pre-auth lookups (login/register/API-key verification). Must be **`renly_admin`** — `BYPASSRLS`, not a superuser, a member of the owner — not the owner itself, which the `FORCE`d policies apply to. Left unset it falls back to `DATABASE_URL`, and that work then reads nothing (login included)                                                                                                                                                                                                                                                                                                                     |
| `JWT_SECRET`                  | Yes      | —                               | Secret key for signing JWTs; min 32 chars, validated at startup. Must match `NEXTAUTH_SECRET` on the frontend                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `JWT_ALGORITHM`               | No       | `HS256`                         | JWT signing algorithm                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `JWT_EXPIRE_MINUTES`          | No       | `30`                            | Access token lifetime in minutes. Kept short (AUTH-7): the web silently exchanges the refresh token for a new access token at expiry                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `REFRESH_TOKEN_REMEMBER_DAYS` | No       | `30`                            | Refresh token lifetime (days) for a "remember me" login (AUTH-7). Slides on each rotation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `REFRESH_TOKEN_DEFAULT_HOURS` | No       | `2`                             | Refresh token lifetime (hours) for an ordinary (non-remembered) login (AUTH-7). Kept tight so an unchecked login on a shared computer doesn't linger; slides on each rotation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ENVIRONMENT`                 | Yes      | —                               | Deployment environment: `development` or `production`. **No default — the API refuses to start without it**, so a deployment cannot run as development by accident. In `production`, `/docs` `/redoc` `/openapi.json` are disabled and debug/tracebacks are off                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `SENTRY_DSN`                  | No       | —                               | Sentry DSN for API error tracking; empty = Sentry off. The environment tag comes from `ENVIRONMENT`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `CORS_ORIGINS`                | No       | `http://localhost:3000`         | Comma-separated list of allowed CORS origins (e.g. `https://app.renly.com,https://renly.com`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `TRUSTED_PROXY_COUNT`         | No       | `0`                             | Number of trusted reverse proxies in front of the app, used to read the real client IP from `X-Forwarded-For` for rate limiting. `0` = reached directly. Behind a proxy/LB, set to the hop count or per-IP limits collapse onto the proxy address                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `INTERNAL_API_SECRET`         | No       | —                               | Secret shared with the web server (never the browser); min 32 chars, validated at startup. Must equal the web app's `INTERNAL_API_SECRET`. The web server's own calls (login, token refresh, the signup context) reach the API from its address; with this set, they are rate-limited by the client IP the web server names in `X-Renly-Client-IP`, honoured only when `X-Renly-Internal-Secret` matches (constant-time compare). Empty = the header is ignored and those calls share the web server's own limit. See [deployment.md](./deployment.md#client-ips-and-rate-limits)                                                                                                                                                  |
| `WEB_BASE_URL`                | No       | `http://localhost:3000`         | Public base URL of the web app (no trailing slash). Used to build the links embedded in account emails (verification, password reset, invite)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `SIGNUP_MODE`                 | No       | `invite`                        | Registration access mode: `invite` requires a valid admin invite to register (the invite-only access gate); `open` lets anyone register. Only `invite` is used at launch                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `EMAIL_PROVIDER`              | No       | `console`                       | Transactional email provider (SHELL-3): `console` logs the message to the API logs (local dev), `resend` sends via the Resend API. Swappable behind the `EmailService` port                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `EMAIL_API_KEY`               | No\*     | —                               | Resend API key. **Required when `EMAIL_PROVIDER=resend`** (validated at startup); unused for `console`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `EMAIL_FROM`                  | No       | `Renly <onboarding@resend.dev>` | From address for outbound email (e.g. `Renly <noreply@yourdomain.com>`). Must be a verified Resend sender in production: with `EMAIL_PROVIDER=resend` and `ENVIRONMENT=production` the API refuses to start on any `resend.dev` sender, the default included, because that shared domain delivers only to the Resend account owner                                                                                                                                                                                                                                                                                                                                                                                                 |
| `VAPID_PRIVATE_KEY`           | No       | —                               | base64url-encoded P-256 private key of a VAPID pair (RFC 8292), enabling web push. **Validated at startup** (must decode to a 32-byte scalar), because the realistic mistake is a PEM pasted in — which would otherwise boot, report push as available, and 500 the notifications page. Empty (default) means this deployment sends no push at all and the app says so rather than offering a switch that does nothing. There is deliberately **no public-key setting**: the `applicationServerKey` a browser subscribes with is derived from this one, so the pair can never be mismatched — a failure that is otherwise invisible (every browser subscribes happily, every send is rejected)                                     |
| `VAPID_SUBJECT`               | No       | falls back to `WEB_BASE_URL`    | Contact the push service can reach about this deployment: a `mailto:` address or an https URL. The fallback is a valid subject and cannot go stale the way a hard-coded address would                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `FINNHUB_API_KEY`             | No       | —                               | Finnhub API key (INFRA-9): the fallback behind yfinance for US stocks, and the only price source independent of Yahoo. Free tier is 60 calls/minute. Empty (default) **drops it from the chain** rather than failing — every other price provider is keyless, so prices keep working unset                                                                                                                                                                                                                                                                                                                                                                                                                                         |

**Build args vs compile-time constants.** Every `NEXT_PUBLIC_*` value is inlined into the bundle when the web
image is built, so none can change at runtime. Only `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_SENTRY_DSN` are
per-deploy config, passed as Docker build args (`docker/web.Dockerfile`). Every other `NEXT_PUBLIC_*` above is a
compile-time constant: the product default behind an in-app setting (currencies, dollar rate, period presets,
limits, health thresholds), not something a deployment sets. Change one by changing the default and rebuilding.

**Sentry source-map upload (build only).** `next build` also reads `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT`; with the token set it uploads source maps, and without it the build neither uploads nor needs them. They are never read at runtime: `apps/web/.env.example` names them in a comment only. `docker/web.Dockerfile` takes `SENTRY_ORG` and `SENTRY_PROJECT` as build args and the token as a BuildKit secret (`--secret id=sentry_auth_token,env=SENTRY_AUTH_TOKEN`), mounted for the `next build` step alone so it never lands in an image layer or `docker history`; with nothing passed the image builds exactly as without them. The full command is in [deployment](deployment.md#the-deployable-unit--two-images).

**Health thresholds are build-time fallbacks, not fixed rules.** Each of the four above can be overridden per user on the **Alerts & Limits** settings page; the env value is what the settings form shows as its placeholder and what applies until someone changes it. They colour the finance-dashboard footer cards and nothing else — no stored figure depends on them.

**Period preset format:** `NM` = N months, `NY` = N years, `YTD` = year to date. "All" is always appended as the last option. If all four are omitted, the in-code fallback offers `1M`, `3M`, `6M`, `YTD` (plus "All"), the same set `.env.example` sets; when any is set, exactly the ones set are used, in slot order.

## Shared constraints

- `JWT_SECRET` (backend) and `NEXTAUTH_SECRET` (frontend) **must be the same value**. The backend signs JWTs that NextAuth stores in its session, and the backend validates them on every API request.
- `NEXT_PUBLIC_API_URL` must point to the running API server. In Docker, use the service name or host network as appropriate.

## Docker Compose overrides

`docker-compose.yml` boots zero-config: the root `.env` is **optional** (`env_file` long syntax,
`required: false`) and every required var has a working local default. Only the vars needing a
compose-specific default appear under `environment`; everything else comes from the optional root
`.env` (if present) or its in-code default (`config.py`).

| Variable                                              | Service         | Default via compose                                                     |
| ----------------------------------------------------- | --------------- | ----------------------------------------------------------------------- |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | postgres        | `renly` / `renly` / `renly`                                             |
| `DATABASE_URL`                                        | api             | `postgresql+asyncpg://renly_app:renly_app@postgres:5432/renly`          |
| `DATABASE_ADMIN_URL`                                  | api             | `postgresql+asyncpg://renly_admin:renly_admin@postgres:5432/renly`      |
| `JWT_SECRET`                                          | api             | dev placeholder (override via shell or root `.env`)                     |
| `WEB_BASE_URL`                                        | api             | `http://localhost:3000`                                                 |
| `ENVIRONMENT`                                         | api             | `development` (required by the api; no in-code default)                 |
| all other API vars                                    | api             | optional root `.env` (`env_file`, `required: false`) → in-code defaults |
| `NEXT_PUBLIC_API_URL`                                 | web (build arg) | `http://localhost:8000`                                                 |
| `NEXT_PUBLIC_SENTRY_DSN`                              | web (build arg) | empty (Sentry off)                                                      |
| `NEXTAUTH_URL`                                        | web             | `http://localhost:3000`                                                 |
| `NEXTAUTH_SECRET`                                     | web             | same dev placeholder as `JWT_SECRET`                                    |
| `NODE_ENV` / `PORT`                                   | web             | `production` / `3000`                                                   |
